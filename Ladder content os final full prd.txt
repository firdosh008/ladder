1. Product Philosophy
One job: help founders make videos. Every design decision is evaluated against a single
question — does this get the user closer to hitting record?

Ladder Content OS is a video production assistant. Research, ideation, scripting, scene
generation, thumbnail creation, and knowledge accumulation all happen on the user's behalf.
These capabilities surface as intelligence, never as features to manage.

1.1 Five Design Principles
1. Outcome-first navigation
Navigation reflects what the user is trying to accomplish, not how the system is structured.
"Make a Video" is a primary action. The user never needs to understand what a knowledge
graph is to benefit from one.
2. The video idea is the atomic unit
Everything lives inside a video idea: script, scene outline, walkthrough output, thumbnail, and a
persistent AI chat that can modify any of it at any time.
3. Shortest path to value
Onboarding is 3 steps. Script streams automatically on studio entry. Scene outline generates
alongside the script. No buttons to click to start generation. Every default is the right answer for
80% of cases.
4. AI is the engine, not the feature
No button is labelled "Generate with AI." Buttons say what they do: "Write my script," "Build
scene," "Generate thumbnail." The user does not need to know or care which model is running.
5. Invisible intelligence
The knowledge graph never appears as a feature to manage. It surfaces as moments: a
contextual hint in the studio, a pre-filled structure based on past patterns, ideas that feel
increasingly personal over time.

Option 1 — Pick from existing ideas
• Shows top ideas from the ideas table ordered by opportunity_score DESC, status = new

or in_progress.
• Clicking any idea navigates directly to /studio/:sessionId — no intermediate screen.
• "+ N more" expands an inline list of remaining ideas without navigation.
• If zero ideas exist: card is dimmed, arrow points to Option 2.

Option 2 — Research and generate
• User enters a keyword, topic statement, or question. This is a targeted research trigger

— not a general weekly sweep.
• On "Research this ->": research_agent runs with this specific input as the focus query.

Returns 3-5 ideas in approximately 15 seconds.
• Results appear inline inside the card as selectable items. User picks one.
• Picking an idea navigates to /studio/:sessionId with that idea pre-loaded.

• User pastes a long-form post, newsletter, thread, article, or document.
• On "Extract and build ->": content_extract_agent processes the pasted content, rewrites

• Source content is stored linked to the idea so the user can reference it during recording.
• Navigates to /studio/:sessionId with the extracted idea and draft script pre-loaded.

3. Onboarding
Get to value in under 3 minutes. Collect the minimum context for a first useful generation.
Everything else fills in progressively.

3.1 Three Steps
Step 1 — Who are you? (60 seconds)
"In one sentence, what do you do and who do you help?" One optional follow-up if the answer is
under 5 words. Two inputs maximum. Builds the positioning field of user_profile.

Step 2 — Who do you sound like? (30 seconds)
"Which creator's style do you want to sound like?" Free text with suggestion chips: Greg
Eisenberg, Nick Saraev, Lenny Rachitsky, David Perell. One name seeds the voice profile. The
system learns more from script edits over time.

Step 3 — Make your first video
The Make a Video entry screen appears directly inside the onboarding frame. No confirmation
screen. The user is in the product. Onboarding completes the moment they enter the Video
Studio — onboarded_at is written then.

3.2 Progressive Profile Building
• After first script: "Does this sound like you? Edit anything that feels off." Edits become

voice training data.
• After 3 videos: Library > What I Know shows a "Complete your profile" prompt with

remaining fields and concrete explanations of what each field improves.
• After YouTube connected: performance data feeds the knowledge graph automatically.
• Profile completeness score (0-100%) shown as a progress bar. Each incomplete field

shows one sentence explaining how filling it improves output.

4. The Video Idea — Atomic Unit
The video idea is the container for everything. Script, scene outline, walkthrough output,
thumbnail, version history, and a persistent AI chat. Nothing about a video lives outside its idea.

Every video starts as an idea — sourced from the research agent, extracted from a newsletter,
generated from a targeted keyword search, or extracted from pasted content. Each idea holds:

• Title and body (user's own notes and context)
• Idea type — determines default output format
• Opportunity score and outlier score
• Source link — for content-extracted ideas, the original pasted content is stored and

linkable
• Script — talking points per scene and transition statements (not word-for-word copy),

versioned
• Scene outline — text-based structural preview, editable, approved before scene build
• Walkthrough output — Excalidraw, Notion (post-MVP), or Gamma depending on idea

type, versioned
• Thumbnail — 3 variants generated after scene is built, stored as artifacts
• AI chat — always visible, scoped to this idea, capable of modifying script, outline, output,

and thumbnail
• Brand — which brand this video represents
• Target duration — default 20 min for AI-generated ideas, derived from content for

pasted-content ideas

4.1 Idea Types and Output Formats
Idea Type Default Output
Systems / Architecture Excalidraw — dark canvas, hand-drawn diagrams, flow diagrams,

architecture maps. Default for most technical content.
Framework / How-to Notion doc — structured walkthrough, headers, steps, callouts.

Shareable as lead magnet. (Post-MVP)
Pitch / Proposal Gamma — polished designed presentation for content where

production quality signals credibility.
Case study / Story Excalidraw — narrative flow diagram, timeline or before/after structure.

The moment a user enters the studio from any entry path, two things happen simultaneously
with no button click:

1. Script begins streaming section by section via SSE. User sees text appearing before the
page finishes loading. No loading screen, no spinner on a blank area, no "Generate

2. Scene outline generates alongside the script. By the time the script is complete, the
scene outline is ready below it.

Exception: Option 3 (pasted content). The content_extract_agent runs first and returns a draft
script. The studio opens with this pre-loaded — streaming is not used for this path since the
script is derived from provided content, not generated fresh.

and body.

5.3 Script Format
The script is NOT a word-for-word teleprompter. It is a structured guide for a natural Loom
recording. Format per section:

## Section Title · N min

Talking points:
. What the problem actually looks like in production
. The three failure patterns you will see
. Why most teams do not catch this until it is too late

Transition to next section:
-> "So the question becomes -- what does a production-ready

architecture actually look like? Let me show you."

• Talking points are speakable bullets — enough to know what to say, not how to say it
exactly.

• Transition statements are written out in full — these are the connective tissue of the
video and need to feel natural, not improvised.

• Each section shows estimated duration. Total duration shown at the top of the script.

• Scripts are versioned. Each regeneration creates a new version. Version selector on the

• For pasted-content ideas: the script is a natural rewrite, not a summary. The agent

5.4 Scene Outline
Appears below the script after a thin Cinnabar divider. Generates automatically when the script
completes — no button click. Displayed as an editable numbered text list:

Scene outline -- 8 frames

Frame 1: Title card -- "Why AI agents fail in production"
Frame 2: The 3 failure modes -- diagram with 3 nodes
Frame 3: Context collapse -- flow diagram showing token overflow
Frame 4: Tool overload -- comparison table (right vs wrong)
Frame 5: No fallback logic -- decision tree diagram
Frame 6: The production-ready architecture -- layered diagram
Frame 7: Implementation checklist -- 5-step numbered list
Frame 8: CTA + summary card

• Every frame is inline-editable. User can rename frames, change diagram type
descriptions, reorder, add, or delete frames directly in the text.

• The AI chat can modify the outline: "combine frames 3-5 into one overview frame" or
"add a before/after frame before frame 6."

• "Approve and build scene ->" is the only button that triggers full scene generation.
Enabled only after the outline exists. User approves structure before the expensive build
step.

5.5 Scene Generation — Excalidraw
Tapping "Approve and build scene" calls build_scene. For Excalidraw output:

• Agent generates a complete .excalidraw JSON file from the approved outline.
• JSON is stored in Supabase Storage. A shareable URL is generated.
• URL is encoded as excalidraw.com/#json=[base64-encoded-content] so it opens directly

in the Excalidraw web app in a new tab. No download, no file management.
• "Open in Excalidraw ->" card appears in the studio. User opens, reviews, makes direct

canvas edits for final polish, then opens Loom and records.
• "Regenerate scene" button appears below the open link. Triggers full rebuild from the

current approved outline.
• Scene versions are tracked. Each regeneration creates a new artifact version. Version

selector accessible via small dropdown.

Excalidraw JSON generation requirements
• Valid .excalidraw JSON format — must open without errors in excalidraw.com.
• Dark mode compatible — dark background (#1A1A2E or similar), light text, Cinnabar

(#E8442A) accent color for key elements.
• Hand-drawn style — roughness: 1, strokeStyle: "hand-drawn" on all elements.
• Logical spatial layout — left-to-right or top-to-bottom flow. No overlapping elements.

Generous spacing between frames.
• Element types matched to frame descriptions: "flow diagram" = rectangles + arrows,

"comparison table" = grid, "decision tree" = diamonds + branches, "architecture diagram"
= layered boxes, "checklist" = vertical list with circles.

• Text labels on all elements must match the outline frame titles exactly — required for
screenshot-to-edit label matching.

5.9 The AI Chat Panel
Always visible on the right side of the studio. Never collapsed. Resizable by dragging the panel
divider. The primary interface for refinement after initial generation.

Context pre-loaded at all times: idea title and body, current script version, current scene outline,
user voice profile, top-K knowledge_nodes (this user only), last 15 chat turns verbatim, older
turns as rolling summary.

Three interaction modes

Mode 1 — Text refinement
"Make the opening more contrarian." "Cut the framework section." "Add a transition after point
3." "Rewrite the problem section to be sharper." Produces updated script sections or outline
frame edits that update in the left panel in place.

Mode 2 — Screenshot-to-edit
User takes a screenshot of the current Excalidraw canvas, pastes it into the chat input, and
types what to change: "Move the architecture box to the right and add an arrow from it to the
outcome node."
Processing pipeline: Claude Vision parses the screenshot, identifies elements by text labels and
positions, maps them to element IDs in the stored .excalidraw JSON using label matching,
generates a surgical diff of only the changed elements, edge function applies the diff, generates
updated Excalidraw URL, studio_session.excalidraw_url updated, new artifact version created.
Fallback: if label matching fails, agent asks: "I could not identify that element — can you tell me
its exact label text?" Never silently applies wrong edits.
The chat input area shows a placeholder hint when an Excalidraw scene exists and no text has
been typed: "Paste a screenshot to edit the scene, or type a message."

Mode 3 — Full scene regeneration
"Regenerate scene" button sits above the chat input, visible only after a scene has been built.
Triggers build_scene from the current approved outline. For structural overhauls where surgical
edits would be slower.

Skill.md injection
A "Inject skill.md" dropdown sits above the chat input. It shows the list of skill.md files the user
has uploaded in Settings. Selecting one injects its content into the next message's context.
Useful when asking the agent to follow a specific framework or SOP for a particular type of
content.

Error recovery
• If stream_script fails mid-stream: a "Retry" button appears in the script area showing

exactly where the stream stopped. Retrying resumes from the last complete section, not
from scratch.

• If build_scene fails: the outline remains intact. "Try again" button re-triggers build_scene.
The user never loses their approved outline.

• If the Excalidraw URL fails to open: a "Download .excalidraw file" fallback link appears
below it.

• On slow connections: a "Taking longer than expected..." message appears after 15
seconds on any generation. Progress is shown for what has completed so far.

7. Library
The intelligence infrastructure layer. Four tabs. Visited weekly at most — not a primary workflow
destination. This is where the system's intelligence comes from.

7.1 What I Know
The user's full knowledge profile. The most important page in Library.

• Profile completeness score: progress bar (0-100%). Each incomplete field shows one
concrete sentence on what improves.

• Editable sections: Who I Am (positioning), Who I'm Talking To (audience), How I Sound
(voice — auto-built from script edits, plus any sample writing provided), Creators I
Emulate, Things to Avoid.

• Each field: click to edit inline, saves on blur.
• Topic territory: three flat lists — Covered (tags used 3+ times), Thin coverage (1-2

times), Open gaps (research agent flags). Each open gap has "Make a video about this
->" routing to /make with topic pre-seeded.

• Brands shortcut: link to Settings > Brands.

7.2 Knowledge Graph
Visual and editable view of everything the system has learned about this user. Two sub-
sections:

Auto-accumulated knowledge
• Shows a feed of what has been added to the knowledge graph automatically: scripts

generated, ideas accepted, YouTube transcripts processed, newsletter ideas extracted.
Each entry shows source type, date, and a summary of what was learned.

• User can delete individual entries if they want to remove something from the graph.

Manual knowledge feed
• "+ Add knowledge" button: opens a text input where the user can paste their own

frameworks, SOPs, positioning statements, product documentation, case studies, or any
IP they want the system to know about.

• Accepts plain text, markdown, or pasted documents.
• Each manual entry is tagged, embedded, and added to knowledge_nodes with

source_type = manual.

15. Risks and Mitigations
Excalidraw JSON renders poorly
Cramped layouts, overlapping elements, illogical flow. Mitigation: engineer builds a validation
step checking bounding boxes for overlaps before returning the URL. The scene outline
approval step catches structural problems first. edit_scene handles spatial corrections. Direct
canvas editing in Excalidraw handles final polish. The bar for "good enough to record over" is
lower than pixel-perfect.

Screenshot-to-edit label matching fails
Claude Vision cannot reliably map a screenshot element to its JSON ID if labels are ambiguous
or truncated. Mitigation: agent asks "I could not identify that element — can you tell me its exact
label text?" before attempting any edit. Full regeneration from outline is always one tap away.

Cross-user knowledge graph data leakage
Highest-severity risk. Mitigation: unit test attempting cross-user retrieval fails CI if it succeeds.
Every pgvector query includes WHERE user_id = :uid before similarity search. RLS on
knowledge_nodes is a second layer. Both must be in place before any user other than Shiv
accesses the system.

"Feels like me" fails after 3-step onboarding
With only a positioning sentence and one creator name, the first script may feel generic.
Mitigation: the AI chat is always visible and the user can refine immediately. "Does this sound
like you?" prompt after the first script captures voice training data. By the third video the system
has enough signal.

stream_script fails or stalls
Mitigation: if SSE fails mid-stream, a "Retry from [section name]" button appears. Retrying
resumes from the last complete section. If SSE is unavailable entirely, fallback to non-streaming
mode — script appears after a 10-15 second wait.

BYOK model misconfiguration causes silent failures
A user configures a model with an incorrect API key or selects a model not available on their
plan. Mitigation: Settings > Models shows real-time API key validation (test call on save). If a

function call fails due to model error, the studio shows "Model unavailable — check Settings >
Models" with a direct link. Never silently falls back to a different model without the user knowing.

Thumbnail quality is inconsistent
AI-generated thumbnails are notoriously variable. Mitigation: always generate 3 variants. The
reference thumbnail URL input is the single most effective quality lever — users should be
nudged to provide one. The "Refine" button on each variant gives a quick iteration loop. This is
expected to be a high-touch workflow for the first few videos until users find their reference
style.

API costs with 9 users
At approximately $0.15-0.30 per idea generation, $0.50-1.00 per script, $0.30-0.60 per scene,
and $0.10-0.20 per thumbnail, 9 users at moderate usage is approximately $400-700 per month
total across all providers. BYOK in v1 means each user pays for their own usage directly. The
usage_log table allows Shiv to see aggregate usage in the admin dashboard. Per-function
model selection (use Haiku for cheap tasks, Sonnet for important ones) is the primary cost
optimisation lever.
